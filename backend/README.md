# Отправка подарков через Cloudflare

Сайт остаётся на GitHub Pages. Worker принимает сертификат и аудио и хранит их в **закрытом R2 bucket**. Получатель открывает ссылку на GitHub Pages; страница получает подарок через API, проигрывает существующую анимацию и даёт скачать исходный сертификат.

## Что нужно для запуска

1. В своём аккаунте Cloudflare включить R2 и создать bucket `thauma-gifts`. Оставить Public Development URL выключенным; публичный домен bucket не подключать. В Settings → Object lifecycle rules добавить удаление объектов с префиксом `gifts/` через **31 день**. API закрывает доступ через 30 дней; запас в сутки позволяет не удалить файлы до срока. Правило также удаляет остатки прерванных загрузок.
2. Создать Cloudflare API token с правами Workers Scripts: Edit и Workers R2 Storage: Edit для этого аккаунта. Добавить его в GitHub repository Settings → Secrets and variables → Actions как `CLOUDFLARE_API_TOKEN`, а Account ID — как `CLOUDFLARE_ACCOUNT_ID`. Секреты не добавлять в код и не отправлять в переписке.
3. После слияния изменений открыть Actions → **Deploy Thauma gift service** → Run workflow на `main`. Адрес Worker будет в результате развёртывания, обычно вида `https://thauma-gifts.<your-subdomain>.workers.dev`.
4. В `assets/sharing-config.js` заменить пустой `API_BASE` на **фактический HTTPS-адрес Worker** без `/api`. Сохранить в `main` и дождаться публикации GitHub Pages. Пустой адрес оставляет сайт в явно обозначенном режиме локального демо.

Не настраивать доступ Cloudflare Access с обязательным входом: получатель должен открывать подарок без аккаунта. Если используются несколько Worker с binding rate limit, выбрать свободный `namespace_id` в `wrangler.jsonc`.

Альтернатива развёртыванию через GitHub Actions (Node.js 22 или новее):

```sh
cd backend
npx wrangler@4 login
npx wrangler@4 deploy
```

Bucket и lifecycle rule также нужны при этом способе. Установка пакетов не нужна для тестов; Wrangler запускается через npx.

## Проверка после запуска

- На GitHub Pages создать подарок с настоящим PDF/изображением и аудио. Должны появиться кнопка «Отправить подарок», ссылка и дата окончания доступа.
- Открыть ссылку в другом браузере или на другом телефоне **без локальных данных отправителя**.
- Открыть упаковку, прослушать поздравление и скачать сертификат. Содержимое скачанного файла должно совпадать с исходным.
- Проверить подарок без аудио и открытие на iPhone/Safari и Android/Chrome.
- Отключить сеть при создании: должно появиться сообщение об ошибке, форма остаётся заполненной, новая ссылка не создаётся. После восстановления связи повторить попытку.

Пока сервер не развёрнут и `API_BASE` пуст, проверка передачи между устройствами недоступна. Существующие локальные демо-ссылки продолжают работать в прежнем браузере.

## Ограничения первой версии

- Для отправки нужен сертификат. PDF, JPG, PNG, WEBP — до 25 МБ.
- Аудио: MP3, M4A/MP4, WAV, OGG, WEBM, AAC — до 25 МБ. Поддержка воспроизведения зависит от браузера получателя.
- Сертификат и аудио вместе — до 30 МБ. Фактический размер потокового запроса проверяется на сервере.
- Подарок доступен 30 дней с момента создания; lifecycle удаляет объекты через 31 день.
- До пяти попыток создания в минуту на IP через Workers Rate Limiting. Это ограничение Cloudflare действует по локациям и не является глобальной квотой затрат. Перед широким запуском настроить уведомления по расходам аккаунта.
- Ссылка содержит случайный 256-битный идентификатор. Любой, кому её передадут, может скачать подарок. Списка подарков, поиска, регистрации и отправки сообщений от имени пользователя нет.
- При неуспешной записи метаданные не публикуются; частично записанные файлы удаляются. После разрыва сети в самом конце загрузки повторная попытка может создать второй подарок; предыдущий автоматически истечёт.
- Ошибка настроенного сервера никогда не подменяется локальной демо-ссылкой. Локальное сохранение используется для предпросмотра и при пустом `API_BASE`.

## API

`GET /api/config` — готовность, поддержка аудио, лимиты и срок.

`POST /api/gifts` — multipart: `metadata` (JSON), `file` (обязательно), `audio` (необязательно).
Метаданные: title ≤60, amount ≤30, message ≤220, один из девяти существующих design, lang ru/en, theme light/dark.
Возвращает `{ id, expiresAt }` только после записи обоих файлов и метаданных.

`GET /api/gifts/:id` — метаданные и сведения о вложениях.

`GET|HEAD /api/gifts/:id/file` и `/audio` — исходные файлы. Все ответы запрещают кэширование; загрузки отдают безопасный MIME и Content-Disposition attachment.

404 — неизвестная ссылка; 410 — срок истёк; 413 — превышение лимита; 429 — слишком частые попытки; 503 — временная недоступность. POST требует разрешённый Origin; чтение по ссылке не требует регистрации. CORS не является авторизацией, доступ обеспечивает непредсказуемый идентификатор.

## Тесты

```sh
cd backend
npm test
```

Проверяются независимые отправитель и получатель, точное содержимое сертификата и аудио, варианты без аудио, старые локальные ссылки, истечение срока, лимиты и проверки типов файлов, CORS, HEAD, ограничение частоты, откат частичной загрузки и ошибки сети. Хранилище в тестах имитирует R2; тесты не обращаются к аккаунту Cloudflare и не заменяют проверку опубликованного Worker на настоящем телефоне.
